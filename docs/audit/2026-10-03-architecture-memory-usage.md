## Comportements corrigés

- La création d'un agent depuis le dessin ou le cockpit conserve cette vue. Le dessin expose des commandes nommées, les agents du projet et un parcours « Confier le dessin à un agent ». La fenêtre de ressource permet de parcourir les fichiers et dossiers locaux et de filtrer les entrées. Les terminaux natifs figurent dans le graphe avec leur état observé ; un processus ouvert ne constitue pas une preuve de travail en cours. Les commandes restent accessibles en fenêtre partagée et sur une largeur de 390 px.
- Les sessions de conception portent une intention `architecture`, en lecture seule. Leur réponse JSON est présentée sous forme de titre, explication, blocs et relations ; la source brute reste consultable. « Valider & importer le dessin » crée une nouvelle page avec sa provenance, sans lancement d'une implémentation ni écrasement du dessin existant. Les anciennes sessions de conception reconnues sont corrigées au prochain message. Une proposition vide, invalide ou issue d'un autre tour reste en attente.
- Duplica sait résoudre ces propositions. L'import du dessin dispose de sa propre permission ; une validation de plan de code reste une permission distincte, par défaut à demander. Le mode ordinateur utilise l'observation puis le clic réel, avec identité de session et de tour. Il ne se replie pas silencieusement vers l'API. Une issue de clic incertaine n'est pas rejouée. `on-request`, lecture seule/écriture projet et les autres permissions sensibles sont conservés.
- Un nouveau message suit l'état réel du tour. Une tâche manuelle encore marquée « En cours » passe à « à revoir » lorsque son tour termine, sans être déclarée accomplie automatiquement. L'interface distingue moteur connecté, tour actif, proposition en attente et tâche à revoir.
- Le détail des agents présente les compteurs cumulés d'entrée, réponse, cache et total. Le cache lu est inclus dans l'entrée, sans double comptage. La consommation comporte de grands graphiques temporels par fournisseur et des comparaisons fournisseur, session, tâche, modèle ou requête. Les mesures absentes restent inconnues ; les cumuls historiques sans date exploitable ne sont pas inventés dans les courbes quotidiennes.
- Les tarifs sont récupérés sur les sources publiques officielles [OpenAI](https://developers.openai.com/api/docs/pricing) et [Anthropic](https://platform.claude.com/docs/en/about-claude/pricing), avec rafraîchissement asynchrone et cache de 24 h. Les modèles sont rapprochés par identifiant exact, les variantes de contexte sont respectées. Un modèle ou un composant de tarif inconnu reste indisponible. Le calcul est un équivalent API, pas une facture d'abonnement ; aucune mesure de quota partagé n'est présentée comme coût de session.
- Le formulaire de souvenir nomme le projet choisi, recherche les chemins et permet de parcourir les sources du projet. Les souvenirs créés ou modifiés sont enregistrés atomiquement en JSON privé dans `.atelier/memory/`, avec schéma `atelier.memory/v1`, sujet, nature, projet, auteur, raison, dates, validation, mots-clés, provenance, résumé et contexte. Export JSON ou Markdown avec en-tête YAML ; les anciens souvenirs restent exportables sans migration destructive ni auteur/validation inventés. La recherche exclut les données privées et les liens sortant du périmètre.

## Limites et état de livraison

Les modifications sont intégrées au code de ce projet. Le bundle `/Applications/Atelier.app` n'a pas été remplacé par cette intervention : une reconstruction est nécessaire pour les retrouver dans cette copie installée. D'autres chats travaillent simultanément dans le même checkout ; leurs modifications ont été conservées et la suite finale porte sur l'état partagé au moment de son exécution.

Les compteurs des CLI natifs restent dépendants des données effectivement observables. Une absence de mesure ne peut pas être corrigée par des chiffres fictifs. Les anciens souvenirs ne sont pas tous réécrits automatiquement en fichiers : la nouvelle représentation durable s'applique à leur création ou modification. Aucune intégration à un outil « Oxygène »/Obsidian n'est affirmée ; JSON et Markdown/YAML fournissent le format de transfert du second cerveau demandé.
