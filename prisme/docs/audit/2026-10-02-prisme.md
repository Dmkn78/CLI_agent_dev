# Prisme — rapport de livraison

Travail demandé le 2 octobre 2026. Tous les fichiers du produit ont été créés
dans `CLI_agent/prisme/`. Aucun fichier préexistant du cockpit parent n'a été
modifié. Trois tâches déléguées ont couvert lecteur, export et tests ; les
corrections et la recette ont été intégrées par l'agent principal.

## Produit livré

Fabrique générique de cours, service Python local et interface JavaScript
native. Dépôt des documents, conservation des sources, génération structurée
par Codex CLI, expériences isolées, lecteur à deux colonnes, notes et export
HTML/ZIP. Les laboratoires d'exemple sont secondaires. Le lanceur, les
dépendances, le prompt et la documentation sont dans le dossier autonome.

Skills réellement utilisés : engineering-workflow et clean-code-workflow
pour l'implémentation, coding-rules pour les conventions, learning-orchestrator,
concept-artifact-builder et retention-loop pour les contraintes pédagogiques.
Computer-use pour la recette. Sites-building a été examiné puis écarté :
le produit demandé reste local. Le profil antérieur de corporate finance a
servi de préférence déclarée, sans inventer de maîtrise ou de déficience.

## Contrôles automatisés

`python -B -m unittest discover -s tests -v` : **60 tests, OK**.
`node --test tests/test_simulations.mjs` : **10 tests, OK**.
`node --check` : tous les modules de `web/`, `templates/export.js` et le
script extrait du document téléchargé sont syntaxiquement valides.
Les 7 tests d'export ont également été relancés après les modifications de CSS.

Couverture significative : préservation du texte et des hashes, PDF textuels,
scans et dessins vectoriels, JPEG orienté et WebP, refus d'un PDF trop dense
sans sources orphelines, couverture de chaque page, sorties invalides,
pagination du catalogue, efforts natifs, permissions, approbations/refus,
threads étrangers, annulation, déconnexion, reprise après redémarrage,
transport JSONL avec vrai sous-processus fictif, frontière HTTP/CSRF/chemins,
notes, archives et relancement de la même bibliothèque.

Des erreurs trouvées pendant les tests ont été corrigées : flux JSON non objet,
fermeture des pipes, événement d'autorisation d'un autre thread, état périmé
après autorisation, validation tardive d'une page PDF dense, et réponse HTTP
masquée par un reset Windows lorsque le corps refusé n'avait pas été consommé.

## Recette navigateur

Service de recette distinct sur le port 8732, données sous
`.prisme/acceptance-data`, avec fournisseur fictif. Aucun appel d'inférence réel.

1. Dépôt de `mon-cours.txt` dans l'interface, titre puis préparation : 1 page
   conservée, 0 page visuelle, original consultable.
2. Connexion fictive : catalogue Alpha/Beta et effort découvert ; création
   avec lecture seule, job observé jusqu'à son résultat.
3. Ouverture d'un parcours de deux sections contenant une expérience HTML
   spécifique, indépendante des quatre laboratoires intégrés.
4. Paramètre au clavier : a = 1,1 donne y = 1,1 et y = 2,2 dans le graphe.
5. Page suivante dans la même section : paramètre 1,1 conservé ; cours déplacé
   de 526 px ; laboratoire et conteneur racine à scrollTop 0 ; position du
   visuel inchangée à 247,546875 px.
6. Défilement jusqu'à la section suivante : sélecteur 02, nouvelle iframe et
   nouveau titre. Réinitialiser recharge correctement cette expérience.
7. Ouverture de la page source, consultation du texte original, note sauvegardée
   et toast de confirmation.
8. Téléchargement effectif du HTML : 64 126 octets. Deux sections, note
   personnelle et original en data URL retrouvés dans son contenu ; script
   sans imports, validé par Node. ZIP contrôlé par les tests HTTP et d'export.

La recette a corrigé des textes trop petits et un déplacement du lecteur lors
du focus d'une iframe. Le conteneur est fixé à la fenêtre et `overflow: clip`
empêche le défilement programmatique du panneau principal. La prédiction
facultative reste repliable pour libérer l'espace du laboratoire.

## Intégration réelle et limites

Contrôle natif en lecture seule : Codex CLI disponible, 11 modèles découverts,
compte non connecté. Aucun credential lu ou copié. Le protocole officiel
consulté est [Codex App Server](https://learn.chatgpt.com/docs/app-server).
Une génération avec le compte réel et les documents personnels doit être
validée après `codex login` ; les fixtures ne constituent pas cette preuve.

Le navigateur intégré a refusé `file://` selon sa politique de sécurité.
L'ouverture hors ligne du HTML n'a donc pas été testée visuellement et aucune
méthode de contournement n'a été utilisée. Son contenu, ses dépendances
embarquées et sa syntaxe ont été contrôlés ; l'ouverture peut être faite par
l'utilisateur dans son navigateur classique.

Le viewport mobile demandé via l'API est resté à 1280 × 720. L'override a été
réinitialisé ; pas de déclaration de réussite pour la recette mobile.
Les vues desktop observées sont 1145 et 1280 px de largeur.

Les expériences générées doivent être confrontées aux sources : le contrôle
de schéma et de références ne certifie pas un calcul ou une démonstration.
Pas d'import Office, de capture/téléchargement de vidéos ni d'OCR autonome.
Python et Codex CLI doivent exister sur la machine de destination.
